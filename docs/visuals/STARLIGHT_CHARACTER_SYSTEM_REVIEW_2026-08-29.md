# Starlight character system review — 2026-08-29

Call: **fix first, then scale**

The existing work contains a strong emotional and material seed, a truthful canonical portfolio, useful research evidence, and a responsible noindex lab. The failure is not a lack of images. It is the absence of one compiled asset decision layer connecting agent truth, cast importance, morphology, audience, surface, provenance, and human approval. The v3 art bible and decision ledger now supply that layer; production expansion remains held until the visual grammar passes one controlled identity test.

| Review area | Verdict | Evidence | Required move |
|---|---|---|---|
| Orchestration and failure | Yellow | Prompt receipts, scoring, stop decisions, and human gates exist, but the previous plan could fan out before a stable identity grammar was selected. | Keep one image per call, require maker/independent critic separation, and stop every weak direction before batch work. |
| Context and memory | Green | Fifty canonical rich cards, a 144-identity lock, immutable v1 provenance, founder review, negative evidence, and versioned decisions live in Git. | Preserve rejected work as labeled studio memory and compile all public consumers from the same ledger. |
| Integration | Yellow | Source cards and web research views are responsible, but production profiles, marketplace, graph, and story surfaces do not yet consume one surface-aware asset contract. | Compile the decision ledger into web data and give every dossier Identity, System, and Workflow views. |
| Cost and routing | Red before v3; yellow after v3 | The flat plan requested 720 generated masters and 5,040 outputs despite only 50 rich cards; 94 expansion profiles are still drafts. | Use 156 generated masters, 5,232 deterministic outputs, and vector-first expansion identities. |

## Top three fixes

1. Prove one ownable identity grammar. Generate and inspect one Lyra identity-lock plate; if it fails, test the non-humanoid Aegis guardian gateway. Do not generate a portfolio batch.
2. Compile one asset truth model into the web experience. Current pixels, target morphology, allowed surfaces, blocked surfaces, approval status, provenance, and operational card truth should arrive together.
3. Separate emotional identity from system state. Story and profile art may create affection; graph state, permissions, confidence, runtime status, and installability remain deterministic and accessible.

## What to build first

- ledger-driven agent dossier data;
- vector micro identity and state grammar;
- one flagship workflow with real artifacts and a human gate;
- one founder-approved signature character application family;
- exact marketplace compatibility and permission cards;
- responsive art derivatives only after master approval.

## What not to build yet

- rich portraits for the 94 expansion drafts;
- ten more unrelated style explorations;
- a 144-face landing-page wall;
- generated status, permissions, charts, UI, or documents;
- large motion or 3D scenes before static hierarchy and performance budgets pass;
- production replacement of the current v1 portraits.

## Studio quality bar

The target is not “Pixar-like,” “game-like,” or “premium AI.” The target is an original Starlight cast system with the production discipline those studios use: silhouette clarity, shape grammar, role-shaped bodies, scale relationships, material logic, behavioral animation, levels of detail, authored environments, and ruthless continuity control. Named studios may inspire production rigor, never imitated surface style.
